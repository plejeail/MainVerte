# MainVerte domain definitions

****This glossary is normative and co-canonical with `Docs/domain_concept.md`.

- **Advice**:
Practical guidance derived from one or more `KnowledgeArticle` entries for a specific context (species, specimen state, or care objective).

- **Alert**:
System-detected condition or rule trigger related to a `Specimen` or `Species` (for example high temperature, low moisture, disease pattern, or missed watering).
  Trigger effects may include:
  - creation or update of an `Event`
  - creation of a `Notification`
  - recommendation or creation of a Task
  - creation or update of a Diagnostic
- **Collection**:
Owned grouping of `Specimen` entities for one gardener.
  Key rules:
  - one gardener may own multiple collections
  - a gardener must retain at least one collection; this will be enforced by the registration and collection-management workflows introduced after the MVP
  - each collection has a `CollectionState`
  - archived collections are not shown in default active views

- **CollectionState**:
Lifecycle state for a `Collection`.
  Allowed values:
  - `active`
  - `archived`

- **Device**:
Physical or virtual equipment connected to the application.
  Device kinds:
  - sensor: observes environmental or specimen-related measurements
  - actuator: performs an action or changes an environment state
  Association rules:
  - a `Device` is not associated directly with a `Specimen`
  - plant context is carried by the `DeviceGroup` that contains the `Device`
  - a sensor `Device` MUST belong to exactly one `DeviceGroup`
  - actuator control scope is explicit and derived from its `DeviceGroup` context and configured control target

- **DeviceGroup**:
Named grouping of `Device` entities used to organize readings, commands, and device views.
  Key rules:
  - one `DeviceGroup` may contain multiple `Device` entities
  - a `DeviceGroup` may be associated with one or more `Specimen` entities
  - sensor navigation is organized around `DeviceGroup` entries in the sensor tab
  - deleting or archiving a `Specimen` does not implicitly delete associated `DeviceGroup` records

- **Device Reading**:
Time-stamped measurement produced by a sensor `Device` and retained for history, alerting, and trend analysis. This is a log, not an event.

- **Device Command**:
Explicit command sent to an actuator `Device`, including requested action, target, status, source, and execution timestamp.

- **Event**:
Time-stamped domain record attached to exactly one `Journal`.
  Event categories (non-exhaustive):
  - care: watering, fertilizing, repotting, pruning, cleaning
  - alert: danger alert triggered
  - lifecycle: specimen acquisition, propagation, flowering, death
  - meta: manual specimen profile update
  Lifecycle rule:
  - an `Event` MUST belong to exactly one `Journal`
  - deleting a `Journal` deletes all its `Event` records

- **ExportArtifact**:
Persisted output generated by an export action (for example CSV, JSON, PDF) with metadata about scope, format, and generation time.

- **Gardener**:
The user of the app.
  MVP bootstrap rule:
  - a default gardener and its default collection are created when the database is initialized

- **ImportBatch**:
Tracked import operation containing source metadata, mapping decisions, duplicate resolutions, and resulting entity changes.

- **Journal**:
Time-ordered set of `Event` records with ownership semantics.
  Lifecycle rules:
  - one `Journal` may contain multiple `Event` records
  - each `Event` belongs to exactly one `Journal`
  - deleting a `Journal` deletes its `Event` records

- **KnowledgeArticle**:
Curated knowledge-base content unit (species page, care guide, troubleshooting note) with source and update metadata.

- **Location**:
Named placement context used to organize specimens (for example room, shelf, greenhouse zone, balcony).

- **Measurement**:
Time-stamped quantitative fact attached to a Specimen, DeviceGroup, or environmental context.
(Examples: PPFD, DLI, temperature, relative humidity, VPD, pot weight, water volume, pH, EC, height, leaf count, flower count, fruit count)
It may come from different sources (gardener, device, import, computation).

- **Notification**:
Message sent to the gardener, typically generated from `Alert` or task logic, with severity level `Info`, `Warning`, or `Danger`.

- **Observation**:
An `event` that represents what the gardener or system sees, not an action (Example: leaf drooping, yellowing, etc.).

- **Prediction**:
An event that represents a forecasted value based on historical data and models.

- **Source**:
Origin metadata describing where a `KnowledgeArticle`, imported data item, or related record comes from (provider, reference URL, license, and attribution fields).

- **Species**:
Template profile shared by plant specimens of the same kind.
  Update rule:
  - species profile updates propagate to linked specimens unless explicitly overridden at specimen level

- **Specimen**:
Individual plant profile with personalized data (display name, pot, current location, and similar attributes) and links to its event history.

- **Tag**:
User-managed label used to categorize and filter specimens, tasks, and knowledge views.

- **Task**:
Care action definition attached to a specimen or collection context (for example water, fertilize, inspect), with origin and scheduling intent.

- **TaskCompletion**:
Recorded outcome of finishing a `TaskInstance`, including completion timestamp and optional note/media, represented as an `Event`.

- **TaskInstance**:
Concrete scheduled occurrence of a `Task` with due date and status.

- **TaskRule**:
Recurrence specification that defines how future `TaskInstance` items are generated for a `Task`.

## Co-canonical maintenance rule

`Docs/domain_definitions.md` and `Docs/domain_concept.md` are both normative.
Any domain evolution must update both files in the same pull request.
Divergence between these files is a specification error.
